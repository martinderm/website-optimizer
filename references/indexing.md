# Indexing and crawling

Crawling is the precondition for everything else. A page that is never crawled
cannot rank no matter how well it is written. In practice, crawling problems
disguise themselves as content problems.

## robots.txt

Controls what may be crawled. It does **not** control indexing: a disallowed URL
that is linked from elsewhere can still appear in results, as a bare link.

```
User-agent: *
Allow: /

Sitemap: https://example.com/sitemap.xml
```

- **Never `Disallow: /` on a live site.** The classic cause is a staging lock
  that was never lifted, or an archive left at `blog_public = 0`. A site with
  this in place looks healthy and is invisible.
- `Disallow` is not access control. Anything sensitive must be behind auth, not
  behind robots.txt.
- Do not block CSS, JavaScript, or images. Blocking them prevents rendering and
  therefore prevents indexing.
- Referencing the sitemap from robots.txt enables auto-discovery, which is the
  cheapest indexing win available.

**Generator note:** Hugo's `enableRobotsTXT = true` emits a `robots.txt` with no
`Sitemap:` line, so the sitemap must be referenced by a `layouts/robots.txt`
template. See `static-sites.md`.

**Measured by** `crawler-files`: `robots.missing`, `robots.blocks_site`,
`robots.blocks_asset`, `robots.sitemap_missing`. What a machine cannot read is
whether a blocked *path* was blocked on purpose: only the usual delivery prefixes
are recognised as mistakes (`/css`, `/js`, `/images`, `/img`, `/media`, `/assets`,
`/fonts`, `/static`, `/uploads`), and the finding names the agent the rule applies
to, because blocking CSS for one named crawler and for everyone are different
decisions.

## XML sitemap

- One `sitemap.xml` listing every indexable URL with `lastmod`.
- Only canonical, indexable URLs. A sitemap containing redirects or noindex
  pages sends mixed signals.
- Generated output counts as a sitemap as long as URLs and `lastmod` are
  accurate; generating it by hand does not improve it.
- Submit it in Search Console and Bing Webmaster Tools.

**Measured by** `crawler-files`: `sitemap.missing`, `sitemap.unreadable`,
`sitemap.empty`, and — against a build — `sitemap.absent_page` and
`sitemap.unsupported_url`. The middle two are worth telling apart: an empty
sitemap means the generator emitted nothing, an unreadable one means a soft 404
answered the request with the site's own HTML.

**Coverage is claimed only from a sitemap that was read.** If the sitemap is
missing or unreadable, no page is reported as absent from it — a failed parse
would otherwise make the whole site look unlisted.

## noindex

The strongest indexing control, and it must come from a page-level meta tag or
the `X-Robots-Tag` header, not from robots.txt.

```html
<meta name="robots" content="noindex">
```

- A `noindex` on a site that is not otherwise discoverable accomplishes nothing.
- Before a launch, check the *built* HTML, not the source. A staging
  `noindex` that survives into production is the most common launch failure.
- `X-Robots-Tag` is the equivalent at the header level and is preferable where
  the HTML is generated by a service you do not control.

## Search Console

- **Domain property** (DNS TXT) covers all subdomains and both protocol
  variants. **URL-prefix** property covers one exact prefix.
- **The prefix rule:** in a URL-prefix property, submit `sitemap.xml` — just the
  filename. Entering the full URL makes the property prepend its own prefix and
  produce a path that does not exist.
- Newly submitted sitemaps often show "could not be read" for 24 to 72 hours
  while Google's scheduler catches up (`observed`, see `sources.md`).
- Verify the sitemap itself before trusting the console: fetch `robots.txt` and
  `sitemap.xml` directly and check for `200`, correct content type, and the
  exact `Sitemap:` line.

```bash
curl -sI https://example.com/robots.txt
curl -s  https://example.com/robots.txt
curl -sI https://example.com/sitemap.xml
```

- Use URL inspection on the sitemap URL with "test live URL" to separate a real
  configuration problem from the queueing delay.
- Request indexing for the handful of pages that matter. It does not submit a
  sitemap; it does not replace one.

## Bing Webmaster Tools

- Import the property from Search Console rather than verifying separately.
- Submit the same sitemap. Bing's index is not a copy of Google's.

## The first external link

A brand-new domain with a perfect sitemap and a verified console can still sit
unvisited for weeks. One real link from an already-indexed domain — a partner, an
institution, a business listing, a profile — shortens that wait.

This is a practitioner heuristic, not a documented Google behaviour
(`partially_supported` in `sources.md`). It costs one email and carries no risk,
which is why it is still worth doing.

## Checklist

- [ ] `robots.txt` reachable, `200`, contains the `Sitemap:` line, no `Disallow: /`
- [ ] `sitemap.xml` reachable, `200`, correct content type, canonical URLs only
- [ ] No `noindex` in the built HTML on any page meant to rank
- [ ] Search Console verified, sitemap submitted as `sitemap.xml` in prefix mode
- [ ] Bing property imported, sitemap submitted
- [ ] At least one external link from an indexed domain
- [ ] Redirects and 404s confirmed after a relaunch (`redirects.md`)
